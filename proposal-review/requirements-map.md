# خريطة متطلبات نظام تأجير السيارات والحسابات

## 1. الفكرة الرئيسية

التصور يعرّف النظام كمسار إدخال موحد للعملية الحالية، ثم ترحيل العملية إلى القسم المناسب مع إبقاء سجل تاريخي دائم للعقود والدفعات وتعاملات العملاء. الهدف التشغيلي هو تقليل تكرار الإدخال، وإظهار حالة كل سيارة وعقد، وفصل الإيجار المستحق والتحصيل والمديونية والالتزامات على المكتب.

في نسخة الآيفون، تُنفذ الفكرة على شكل شاشة تشغيل وقوائم مترابطة بدلاً من ورقة Calc، مع الحفاظ على نفس القاعدة: **عملية واحدة، حفظ واحد، سجل مؤرخ، ثم تحديث الحالة والقوائم تلقائياً**.

## 2. الدورة التشغيلية

| القاعدة | المطلوب | موضع العرض |
|---|---|---|
| دورة المكتب | من اليوم السادس إلى الخامس من الشهر التالي | لوحة التحكم والتقارير والإيرادات |
| البيانات القديمة | تنبيه إلى أن تحليلي الشهرين السادس والسابع غير دقيقين عند قراءة السجلات القديمة | التقارير |
| السيارات غير الصالحة | السيارة التالفة أو غير الصالحة لا تظهر ضمن المتاح | السيارات ونموذج العقد |
| السجل الدائم | لا تُحذف العملية عند إغلاق العقد أو تعليقه أو استرجاع السيارة | تفاصيل العقد وكشف الحساب |

## 3. صف الإدخال والحقول

| الحقل | قاعدة التصور | السلوك المطلوب في الهاتف |
|---|---|---|
| تاريخ العملية | تاريخ العقد أو استلام المبلغ أو تنفيذ العملية | يظهر في كل عملية ويحفظ زمنياً |
| السيارة | قائمة بالسيارات المسجلة | عند التبديل تُختار السيارة الجديدة، وتُسجل القديمة والجديدة |
| هوية العميل | معيار تعريف وبحث | يربط العميل بكل عقوده ودفعاته |
| اسم العميل | الاسم الكامل | عند إضافة عميل جديد يظهر في القائمة ونموذج العقد |
| الجوال | وسيلة التواصل | يحفظ مع العميل ويظهر في كشفه |
| نوع العملية | يومي، شهري، تمديد، استرجاع، تبديل، استلام مبلغ، تعليق، إغلاق | يفتح الحقول والتشعبات الخاصة بالعملية |
| مبلغ التأجير | يومي أو شهري أو قيمة عملية | يستخدم في الحساب ولا يختلط بمبلغ التأخير |
| عدد الأيام | مدة العقد، والشهري أساسه 30 يوماً | يحسب أو يُدخل حسب نوع العملية |
| الإجمالي | قيمة التأجير × المدة/الوحدات | يعاد حسابه قبل الحفظ |
| شبكة وكاش | مبلغ مستلم عبر الشبكة أو نقداً | يحفظان منفصلين داخل الدفعة والتقرير |
| مبلغ إضافي | مبلغ مرتبط بالعملية | يدخل في إجمالي المدفوع مع بيان سببه |
| إجمالي المدفوع | الشبكة + الكاش + الإضافي | يخصم من المستحقات |
| الملاحظات | تفاصيل أو تنبيهات | تحفظ في العملية وسجل العميل |
| رقم العقد | تلقائي للعقد الجديد ومرجع للعقد السابق | رقم قابل للضغط يفتح التفاصيل |

## 4. فروع العمليات

### 4.1 عقد يومي

يختار المستخدم العميل والسيارة ونوع «يومي»، ثم تاريخ البداية والتسليم وسعر اليوم. يحسب النظام الأيام والإجمالي وتاريخ التسليم والأيام المتبقية أو المتأخرة. عند الحفظ يتولد رقم عقد تلقائي، تُحجز السيارة، ويُنشأ سجل عملية `new_contract` مؤرخ.

### 4.2 عقد شهري

يختار المستخدم «شهرياً» ويعتمد النظام وحدة 30 يوماً. يبقى تاريخ التأسيس محفوظاً. عند دخول شهر تأجيري جديد يمكن إضافة قيمة إيجار جديدة مع إبقاء المبالغ منفصلة. مبلغ التأخير الشهري يحسب وفق قرار المستخدم: **السعر الشهري ÷ 30 × عدد أيام التأخير**.

### 4.3 تمديد العقد

يدخل المستخدم رقم العقد السابق، يختار «تمديد»، ويدخل مدة التمديد. يجب أن يبقى رقم العقد نفسه، وأن يضاف التمديد إلى تاريخ التسليم السابق، وأن تسجل العملية في السجل التاريخي دون إنشاء عقد جديد.

### 4.4 استلام مبلغ

يدخل المستخدم رقم العقد السابق وتاريخ العملية، ثم يحدد مبلغ الشبكة أو الكاش والمبلغ الإضافي عند وجوده. تُسجل الدفعة، ويُخصم المبلغ من المستحقات، ولا يتغير تاريخ تأسيس العقد أو تاريخ التسليم ولا ينشأ عقد جديد.

### 4.5 تبديل السيارة

يدخل المستخدم رقم العقد السابق ويختار السيارة الجديدة. يبقى رقم العقد وتاريخ تأسيسه وتاريخ التسليم كما هي، ويُحدّث ارتباط العقد بالسيارة الجديدة. تُحرر السيارة القديمة، وتُحجز الجديدة، ويحفظ السجل السيارة القديمة والجديدة وتاريخ التبديل واسم المنفذ.

### 4.6 تعليق العقد للتعثر المالي

يدخل المستخدم رقم العقد ويختار «تعليق». ينقل النظام العقد إلى حالة معلّق ويحتفظ بالسجل. وفق قرار المستخدم، يُعد العقد متعثراً عندما يكون المبلغ المدفوع أقل من الإيجار المستحق عن الأيام المستخدمة، سواء كان التأخير موجباً أو صفراً. عند تعليق العقد للتعثر تُحرر السيارة من الحجز التشغيلي وفق القرار المعتمد، ولا تظهر ضمن العقود السارية.

### 4.7 إغلاق العقد

يدخل المستخدم رقم العقد ويختار «إغلاق». تتحول الحالة إلى مغلق/منتهي، تُسجل العملية، وتصبح السيارة متاحة لعقد جديد بعد الحفظ. لا ينشأ عقد جديد ولا يُحذف السجل التاريخي.

### 4.8 استرجاع السيارة

يدخل المستخدم رقم العقد وتاريخ الاسترجاع. تتحول الحالة إلى مسترجع، تحفظ العملية، وتُمنع السيارة من الاستمرار ضمن العقود السارية، ثم تصبح متاحة فقط إذا لم توجد عليها صيانة أو حجز آخر.

## 5. الحقول المالية والحالات

| المفهوم | القاعدة |
|---|---|
| الرصيد غير المدفوع | الإجمالي الأصلي ناقص المدفوعات المسجلة |
| مبلغ التأخير | مبلغ مستقل يحسب من أيام التأخير وسعر الوحدة، ولا يُستبدل بالرصيد الأصلي |
| التأخير اليومي | سعر اليوم × أيام التأخير |
| التأخير الشهري | السعر الشهري ÷ 30 × أيام التأخير |
| ساري | تاريخ التسليم لم يتجاوز تاريخ اليوم |
| متأخر | تاريخ التسليم تجاوز تاريخ اليوم |
| معلق | العقد متوقف ولا يدخل في قائمة الساري |
| مغلق | انتهى إدارياً |
| مسترجع | عادت السيارة إلى المكتب |
| طرق الدفع | كاش وشبكة، مع إمكانية التحويل إن كان مفعلاً في النظام |

| العقود السارية | رقم العقد القابل للضغط، العميل، السيارة، السعر، التسليم، الأيام، الرصيد السابق، مبلغ التأخير، الحالة |
| العقود المعلقة | سبب التعليق، تاريخ التعليق، الرصيد، التأخير، سجل العقد |

| التزامات المكتب | المبلغ، التصنيف، السداد، المتبقي، الحالة، التاريخ، المنفذ |
| الصيانة والتالف | السيارة، المشكلة، البداية، النهاية، التكلفة، الملاحظات، ومنع الظهور ضمن المتاح |
| العملاء | إضافة عميل باسم وهوية وجوال، ثم إظهاره فوراً في القوائم ونموذج العقد |

## 7. السجل التاريخي

كل عملية يجب أن تحتوي على نوع العملية، رقم العقد، السيارة المرتبطة وقت العملية، المبلغ، طريقة الدفع عند وجودها، الملاحظات، المنفذ، وتاريخ/وقت الإنشاء. لا يكفي نقل العقد بين القوائم؛ يجب أن يبقى السجل قابلاً للعرض من رقم العقد ومن كشف حساب العميل.

## 8. حدود التنفيذ التي يجب التحقق منها

المسارات البرمجية الحالية تغطي رقم العقد التلقائي، العمليات المنفصلة، الدفع كاش/شبكة، سجل العمليات، تحرير السيارة عند الإغلاق والتعليق والاسترجاع، تبديل السيارة، التقارير والتزامات المكتب، وإضافة العملاء. يجب قبول التمديد الفعلي وتحديث تاريخ التسليم، واختبار انتقال السيارة البديلة وقاعدة التعثر داخل جلسة هاتفية مصادق عليها قبل اعتماد النسخة نهائياً.

## 9. مصفوفة الصلاحيات

| الفرع | المستخدم التشغيلي | المدير | التحقق والسجل |
|---|---|---|---|
| إنشاء عقد يومي/شهري | مسموح | مسموح | عميل وسيارة متاحان، ورقم جديد يولد تلقائياً، وسجل `new_contract` مؤرخ |
| استلام مبلغ كاش/شبكة | مسموح | مسموح | رقم عقد صحيح، مبلغ موجب، طريقة دفع محددة، وسجل `payment` |
| تمديد عقد | مسموح | مسموح | رقم عقد قائم ومدة صحيحة، مع إبقاء الرقم نفسه وتسجيل `extension` |
| تبديل السيارة | مسموح | مسموح | سيارة بديلة متاحة ومختلفة، تحرير القديمة وحجز الجديدة وتسجيل `vehicle_swap` |
| تعليق للتعثر | مسموح | مسموح | تحقق من أن المدفوع أقل من الإيجار المستحق حتى اليوم، ثم تسجيل `suspend` |
| إغلاق العقد | مسموح | مسموح | رقم عقد قائم، تحديث الحالة وتحرير السيارة وتسجيل `close` |
| استرجاع السيارة | مسموح | مسموح | رقم عقد قائم، تاريخ الاسترجاع، تحرير السيارة فقط إذا لم يمنعها سبب آخر، وتسجيل `return` |
| إضافة عميل | مسموح | مسموح | الاسم والهوية والجوال مطلوبة، منع تكرار الهوية، وتحديث قائمة العملاء |
| إدارة التزامات المكتب | غير مسموح افتراضياً | مسموح | إنشاء/سداد/إلغاء الالتزام مقيد بدور المدير وسجل منفذ وتاريخ |
| التقارير وكشف الحساب | قراءة | قراءة | لا يغير البيانات، ويعرض المقبوض والمتبقي والإيرادات وفق دورة 6–5 |
| الصيانة والتالف | مسموح حسب صلاحية الوحدة | مسموح | السيارة لا تظهر ضمن المتاح أثناء الحالة المفتوحة، وكل تغيير مؤرخ |

تُنفذ الصلاحيات عبر حماية الخادم أولاً، ولا تُعد إخفاء الأزرار في الواجهة بديلاً عن التحقق في الـAPI. ويُعد المستخدم المحلي مديراً عند تشغيل إعداد المدير المحلي، بينما تُحترم أدوار `admin` و`user` في الجلسات المصادق عليها.
